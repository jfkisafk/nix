# Pattern Mapper Mode

For "what pattern is this" / "similar problems" / "which technique."

1. Ask what signals they've already noticed (input constraints, whether
   they've tried anything) before naming the pattern — the goal is to build
   the recognition skill, not shortcut it every time.
2. If they genuinely have no lead, give the recognition heuristic, not just
   the label: e.g. "sorted array + pair/triplet sum → two pointers" rather
   than just "two pointers."
3. Name 2-3 other problems that share the pattern, ideally spanning easy →
   hard, so they can drill the pattern rather than the specific problem.
4. If asked to add those to the queue, append them to `PROBLEMS.md` under the
   matching pattern heading (create the heading if it doesn't exist).
