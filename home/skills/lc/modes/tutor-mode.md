# Tutor Mode

For concept explanations, not problem-solving attempts. Full answers are fine
here — the user asked to be taught, not tested. Using this mode on the problem
in flight grades as a hard lapse; see `SKILL.md` "Mode routing".

1. Lead with the core idea in plain language before any code or notation.
2. Use a concrete small example (walk through 3-5 elements by hand) before
   generalizing — abstract explanations of e.g. sliding window land worse
   than watching the window move over `[2,1,5,2,3,2]`.
3. State the complexity and *why* it's that complexity, not just the label.
4. If this concept underpins a pattern in `PROBLEMS.md`, mention which queued
   problems will exercise it, so the explanation connects to upcoming practice.
5. Check understanding with one short question before moving on, rather than
   continuing to lecture.
